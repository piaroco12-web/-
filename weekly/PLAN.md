# 토요일 09시 주간 AI 활용 분석 보고서

보고 대상은 충남소프트웨어교육체험센터 파견교사이자 교육전문직 시험을 준비하는 사용자다. Codex는 사실 기록·통계·변환을 담당한다. 분석과 조언의 저자는 Claude다.

## 주간 인계 (한국시간)

| 시각 | 담당 | 산출물과 다음 단계 |
| --- | --- | --- |
| 금요일 밤까지 | Codex | `weekly/logs/YYYY-Www/codex.md`에 완료·다음·요청과 근거를 기록한다. 주중에도 같은 파일을 갱신할 수 있다. |
| 토요일 07:00 | 뮤즈 | 기존 [뮤즈 명령서](../team/orders/muse-weekly.md)에 따라 노션을 정리해 같은 주차의 `notion.md`를 전달한다. 서술형 정리 끝에는 아래 집계표를 붙인다. |
| 08:00 | Claude | 각 담당 브랜치에서 해당 주차의 기록을 수집한 후 통계를 실행한다. 노션 원본과 작업기록을 대조하고, 사용자 목표(있으면 `goals.md`)를 읽어 분석한다. |

주차는 토요일 발행일의 ISO 주차다. W47은 2026-11-14(토) 00:00 이상, 11-21(토) 00:00 미만이며 제출 파일은 `weekly/reports/2026-W47_주간분석.docx`다. Codex 작업은 `claude/weekly-ai-analysis-report-kuezvx`에서 파생한 `codex/weekly-report`에서 진행한다. [저장소 규칙](../AGENTS.md)과 [파일 소유권](../team/README.md)을 따른다.

## 08시 통계

저장소 루트에서 Python 3.9 이상과 Git, 저장소 읽기 권한이 있는 GitHub CLI로 실행한다.

```sh
python scripts/weekly/stats.py --week 2026-W47
```

- 커밋은 이 저장소 원격 브랜치 전체를 새로 조회한 뒤 해당 기간의 커미터 시각으로 추린 고유 SHA 수다. PR은 같은 기간에 생성된 모든 상태의 고유 PR 번호 수다.
- AI별 작업은 노션 공통 로그의 날짜·도구·유형·원본 행을 기준으로 센다. 요청은 별도 합계로 표시한다. 서술에서 같은 작업이 여러 번 등장해도 원본 ID 한 건만 센다.
- 뮤즈는 공통 로그 조회를 끝낸 경우 아래 블록을 한 번 넣는다. 열은 탭으로 구분하며 원본 칸은 행 URL 또는 UUID다. 실제 0건이면 헤더만 남긴다. 수집이 불완전하면 표를 생략하고 누락 사유를 본문에 적는다.

```notion-tsv
날짜	도구	유형	원본
```

결과는 `weekly/logs/YYYY-Www/stats.json`에 저장한다. 각 항목의 상태, 집계 범위와 조회 시각, 근거 SHA·PR 번호·노션 ID를 포함한다. 원본 식별자가 있는 통계와 뮤즈 인계표는 비공개로 전달해 실행 폴더에서 사용하고, 공개 저장소의 작업기록은 공개 가능한 근거를 인용한다. 종료 코드 0은 전체 정상, 2는 결과 파일에 일부 ‘확인 필요’ 항목이 있음을 뜻한다(인자 형식 오류도 2이므로 실행 메시지와 주차를 확인한다). Claude는 미확인 수치를 비워 두고 확보된 근거로 분석을 이어간다.

## 08시 45분 DOCX

Claude는 `weekly/reports/YYYY-Www_주간분석.md`에 아래 네 제목을 순서대로 쓴다. 각 영역은 실제 사례와 원본 링크, 해석, 다음 주 행동 하나와 점검 기준을 포함한다. 하위 제목은 `###`을 쓴다.

```markdown
## AI 활용 역량
## 교육전문직 준비
## SW교육체험센터 업무
## AI 활용 방식
```

첫 쪽은 AI 요청·검증 역량과 최우선 행동, 둘째 쪽은 본인의 장학사 시험 연습, 셋째 쪽은 센터 교육·행정 성과, 넷째 쪽은 도구 간 인계와 일상 비서 활용을 다룬다. AI의 활동 건수를 사용자 실력 향상의 근거로 대신 쓰지 않는다. 개인정보를 가리고 미확인 사실은 표시한다.

실행 환경에 python-docx, Pandoc, LibreOffice(soffice), Poppler(pdftotext), Noto Sans CJK KR 글꼴을 준비한다.

```sh
python scripts/weekly/build_docx.py --week 2026-W47
```

[편집 가능한 4쪽 양식](templates/weekly-report.docx)의 용지·스타일을 사용한다. DOCX를 PDF로 임시 렌더링해 총 네 쪽과 각 제목의 쪽 위치를 검증한 후 제출 경로에 저장한다. 영역이 빠지거나 분량이 넘치면 Claude가 원고를 수정하고 재실행한다. 같은 주차 재실행 시 검증을 통과한 결과만 기존 파일을 교체한다.
